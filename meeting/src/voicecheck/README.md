# voicecheck（声の分析カルテ）

翻訳した声（合成音声）が、**本人の声にどれだけ似ているか**を数字にして、Excel にまとめる道具です。
似ている度合い（SIM）のほかに、声の高さ・抑揚・音色・話す速さ・音量がどれだけ違うかも出ます。

- 先に「現状値」を測り、そのあとで改善（手本の差し替えなど）の効果を同じ物差しで比べるための**測定器**です。
- パソコンだけ（GPU なし）で動きます。Mac（Apple Silicon）と Windows で使えます。
- 会社の会議音声を外部に送る機能はありません。ただし、**初回だけ** ECAPA のモデル（約 85 MB）をインターネットからダウンロードします。

---

## 1. 準備（最初に1回だけ）

### 1-1. uv を入れる

uv は、Python と必要な部品をまとめて用意してくれる道具です。

- **Mac**: ターミナルで
  ```
  curl -LsSf https://astral.sh/uv/install.sh | sh
  ```
- **Windows**: PowerShell で
  ```
  powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/install.ps1 | iex"
  ```

入れたら、ターミナル（PowerShell）を一度閉じて開き直します。

### 1-2. 部品を入れる

プロジェクトのフォルダ（`pyproject.toml` があるフォルダ）に移動して、次を実行します。

```
uv sync
```

これで Python 本体と、必要な部品（torch、speechbrain など）が全部入ります。初回は数分かかります。

動いているか確認します。

```
uv run voicecheck --help
```

3つのコマンド（`compare` `calibrate` `features`）の説明が出れば成功です。

> 以降のコマンドは、すべて**プロジェクトのフォルダで**、先頭に `uv run` を付けて実行します（Mac も Windows も同じ）。
> `voicecheck ...` の代わりに `uv run python -m voicecheck ...` と書いても同じです。

### うまくいかないとき

| 症状 | 対処 |
|---|---|
| Mac で `pyworld` のところでエラー（コンパイルできない） | `xcode-select --install` を実行してもう一度 `uv sync`。それでもだめなら `uv sync --no-install-package pyworld`。声の高さを pyworld の代わりに librosa で測る方式に自動で切り替わります（少し遅く、値がわずかに違います）。 |
| 埋め込みのモデル（torch など）を入れたくない・入らない | `uv sync --no-group embedders`。類似度（SIM）は出ませんが、声の特徴量は測れます。 |
| `ecapa: モデルを取得・読み込みできません` | 初回だけネット接続が必要です（会社のプロキシ越しだと失敗することがあります）。一度成功すれば、次からはネット無しで動きます。 |
| `ファイルに書き込めません` | 出力先の Excel を開いたままです。閉じてからやり直します。 |
| 文字化けする（Windows） | 動作には影響しません。PowerShell で `chcp 65001` を実行すると直ることがあります。 |

## 2. 3つのコマンド

### 2-1. `features`：声の特徴だけを測る（いちばん簡単）

wav ファイル1つ、または音声の入ったフォルダを指定します。

```
uv run voicecheck features --in profiles/A --out outputs/features.xlsx
```

Windows でフォルダを指定するとき: `--in C:\Users\あなた\Documents\voices\Aさん`（スペースがあるときは `"` で囲む）。

- フォルダの中に話者ごとのサブフォルダがあれば、「話者ごと」シートにサブフォルダ別の平均が出ます。
- 登録音声の「声の高さ（中央値）」「抑揚の幅」などの**基準値**を知りたいときに使います。

### 2-2. `calibrate`：合格ライン（しきい値）を決める

「同じ人どうし」と「別の人どうし」の SIM を全部の組み合わせで測り、2つの分布の境目（EER しきい値）を出します。

**まず、登録音声を話者ごとのフォルダに分けて置きます。**

```
enroll/
  Aさん/  01.wav  02.wav  03.wav  ...
  Bさん/  01.wav  02.wav  ...
  Cさん/  ...
```

- 話者は**2人以上**、1人あたり**2ファイル以上**（多いほど安定。目安：5人以上、1人5ファイル以上）。
- 会社の音声は使わず、自分の声・同意をもらった模擬会議・公開データを使います。

```
uv run voicecheck calibrate --enroll-dir enroll --out outputs/calib.xlsx
```

画面にも結果が出ます（例：公開音声 40人での実測）。

```
[ecapa]       EER 1.13%  おすすめしきい値 0.323
[resemblyzer] EER 4.32%  おすすめしきい値 0.691
```

Excel の「較正」シートには、しきい値と、SIM の分布（0.05 刻みの件数）が出ます。
グラフにするには：分布の表（「区間」「同じ人の件数」「別の人の件数」の列）を選び、**挿入 → 縦棒グラフ（集合縦棒）**。
2つの山が離れているほど、その埋め込みは本人と別人をよく見分けられます。

### 2-3. `compare`：手本と合成音声を比べる

#### ① pairs.csv を作る

Excel で表を作り、**名前を付けて保存 → 「CSV UTF-8（コンマ区切り）」**で保存します（普通の「CSV（コンマ区切り）」でも読めます）。

| 列 | 必須 | 意味 |
|---|---|---|
| `speaker` | 必須 | 話者の名前（集計の単位になります） |
| `ref` | 必須 | 本人の手本（登録音声）の wav。**複数あるときは `;` で区切る**（例：`ref/a1.wav;ref/a2.wav;ref/a3.wav`）。複数のときは、その平均と比べます |
| `test` | 必須 | 評価したい音声（合成音声など）の wav |
| `source` | 任意 | 元の発話の wav。あると「元の発話との類似度」「元の発話に対する話速の比」なども出ます |
| `label` | 任意 | 条件の名前（`baseline`、`profile_ref` など）。条件ごとの集計が「話者ごと」シートに出ます |
| `emotion_src` | 任意 | 元の発言の感情ラベル |
| `emotion_test` | 任意 | 評価音声に感情判定をかけた結果。両方あると「感情一致」が出ます |

例（`pairs.csv`）：

```
speaker,ref,test,label,source,emotion_src,emotion_test
Aさん,profiles/A/r1.wav;profiles/A/r2.wav,outputs/baseline/line001.wav,baseline,data/orig/line001.wav,angry,neutral
Aさん,profiles/A/r1.wav;profiles/A/r2.wav,outputs/profile_ref/line001.wav,profile_ref,data/orig/line001.wav,angry,angry
```

- パスは、pairs.csv のあるフォルダからの相対パスでも、フルパス（Windows なら `C:\...`）でも書けます。
- 見出しは日本語（`話者`、`手本`、`評価`、`ラベル` など）でも読めます。

#### ② 実行する

```
uv run voicecheck compare --pairs pairs.csv --out outputs/report.xlsx --calib outputs/calib.xlsx
```

- `--calib` は、calibrate が作った Excel から**しきい値を自動で読みます**。
- しきい値を直接指定することもできます：`--threshold 0.45`（全部の埋め込みに同じ値）、または `--threshold ecapa=0.32,resemblyzer=0.69`（埋め込みごと）。`--threshold` が `--calib` より優先されます。
- しきい値を指定しなければ、SIM と特徴量の差だけが出ます（赤い塗りと合格率は出ません）。

どのコマンドにも共通のオプション：

| オプション | 意味 |
|---|---|
| `--embedder ecapa` / `resemblyzer` / `all` / `none` | 使う埋め込み。既定は `all`（両方）。`none` は特徴量だけ。使えない埋め込みは警告を出して飛ばし、残りで続けます |
| `--out ファイル名.xlsx` | 出力先（省略時は `report.xlsx` / `calib.xlsx` / `features.xlsx`） |

壊れたファイルや見つからないファイルがあっても止まらず、その行の「備考」に理由を書いて次に進みます。

## 3. Excel の読み方

どの Excel にも「**説明**」シートがあり、そのファイルにある**全部の列の意味と見方**が日本語で書いてあります。迷ったらそこを見てください。「実行情報」シートには、使った設定（しきい値、使った埋め込み、使えなかった機能）が残ります。

### `compare` の Excel

**「行ごと」**（pairs.csv の1行＝1行）

| 列 | 意味 | 見方 |
|---|---|---|
| SIM（ecapa） / SIM（resemblyzer） | 手本と評価音声の話者類似度（コサイン類似度）。手本が複数なら平均（重心）と比べる | 1に近いほど本人に似ている。**しきい値未満は赤く塗られる** |
| 判定 | しきい値以上なら「合格」、未満なら「不合格」 | フィルターで不合格だけ見られる |
| 声の高さの差（半音） | 評価音声 − 手本。プラスなら評価音声のほうが高い | ±1半音以内ならほぼ同じ高さ |
| 声の高さの幅の比 | 抑揚の大きさ（F0 の四分位範囲）の比 | 1に近いほど抑揚の大きさが同じ。小さいと棒読み |
| 傾きの差（dB/oct） | 音色の明るさ（スペクトルの傾き）の差 | 0に近いほど音色が同じ |
| 話速の比 | 話す速さ（簡易）の比 | 1より大きいと評価音声のほうが速い |
| 音量の差（dB） | 発話部分の音量の差 | ±3 dB 以内ならほぼ同じ |
| 重心の差 / CPPS の差 | 音の明るさ／声のはっきりさの差 | 0に近いほど同じ |
| 感情一致 | 感情（元）と感情（評価）が同じか | 両方あるときだけ |
| 備考 | 注意・エラー（1秒未満の短い音声、ファイルが無い、など）。黄色の行は確認 | 空欄なら問題なし |

**「話者ごと」**：話者 × ラベルごとに、SIM の**平均・最小・ばらつき（標準偏差）・合格率**と、特徴量の差の平均。最後に「（全員）」の行があります。`label` で条件を分けておくと、**baseline と改善後を並べて**比べられます。

### `calibrate` の Excel

**「較正」**：埋め込みごとに、同じ人どうし・別の人どうしの SIM の平均、EER（%）、**EER しきい値（おすすめ）**、「厳しめしきい値」。その下に、SIM の分布の件数表と、登録データの内訳（話者ごとのファイル数・時間・注意）があります。

### `features` の Excel

**「行ごと」**にファイルごとの特徴量、**「話者ごと」**にフォルダ別の平均。

| 特徴量 | 意味 |
|---|---|
| 声の高さ（Hz） | F0 の中央値。男性 約100〜130、女性 約180〜250 が目安 |
| 声の高さの幅（半音） | F0 の 25%〜75% の幅（IQR）。抑揚の大きさ |
| 有声率 | 声帯が震えている時間の割合 |
| 音量（dBFS） | 発話部分の音量。0に近いほど大きい |
| スペクトル傾き（dB/oct） | 100 Hz〜5 kHz の傾き。0に近いほど明るい、マイナスが大きいほどこもった音 |
| スペクトル重心（Hz） | 音の明るさ |
| CPPS（dB） | 声のはっきり（周期性）。大きいほどクリア |
| 話速の目安 | 音量の山（音節の核）の数 ÷ 有声の秒数 |

## 4. しきい値（合格ライン）の決め方

**SIM の値は埋め込みの種類で水準が違うので、「0.7 以上なら合格」のような固定の基準は使えません。**

文献の目安は「同じ人の実声どうしで約 0.7、0.5 未満は別人に聞こえやすい」ですが、これは別の測定器での値です (要検証)。実際、公開音声（LibriSpeech test-clean、40人・335発話）での実測は次のとおりでした。

| 埋め込み | 同じ人どうしの平均 | 別の人どうしの平均 | EER | EER しきい値 |
|---|---|---|---|---|
| ecapa | 0.69 | 0.09 | 1.1% | 0.32 |
| resemblyzer | 0.85 | 0.55 | 4.3% | 0.69 |

- ecapa は「同じ人 ≒ 0.7」に近い値でした。
- resemblyzer は**別人どうしでも平均 0.55** と高めに出ます。「0.5 未満が別人」は当てはまりません。
- ecapa のほうが本人と別人をよく見分けられました（EER が小さい）。迷ったら ecapa を主に見て、resemblyzer は確認用にします。

**手順**

1. 登録音声（静かな部屋で録った本人の声。1人あたり複数ファイル）で `calibrate` を実行する。
2. 「較正」シートの **EER しきい値（おすすめ）** を合格ラインの出発点にする。`compare --calib 較正のExcel` でそのまま使える。
3. もっと厳しく「似ている」と言い切りたいときは **厳しめしきい値**（別の人が通るのが 1% 以下になる値）を `--threshold` に書く。
4. **日本語の手本 → 英語の合成のように言語をまたぐと、本人の実声どうしでも SIM は下がります。** 目標値は、同じ人の別言語の実声で較正するのがおすすめです。
5. 目標値は「現状値を測ってから」決める：まず今の方式（baseline）で `compare` を実行して SIM の平均と合格率を記録し、改善後を同じ pairs.csv の形（`label` だけ変える）で測って比べる。

> SIM は人の耳による評価の代わりではありません。主観評価（5段階など）と並べて判断してください。

## 5. 知っておくこと（制限）

- 手本は**静かな部屋・口元マイク**で録った 10〜20 秒を数本用意すると安定します。雑音・反響・電話音質の手本では SIM が低く出ます。
- 1秒未満の音声は値が不安定です（備考に注意が出ます）。
- 「話速」は音量の山を数えた**簡易の目安**です（英語の読み上げ 40 文で、数えた山の数と綴りから概算した音節数の相関は 0.99、数えた数は約 0.9 倍でした）。言語が違うと値そのものは比べられないので、同じ内容どうしの「比」で見ます。
- CPPS・スペクトル傾きは録音条件（マイク・部屋）で変わります。同じ条件どうしで比べてください。
- 8 kHz などサンプルレートの低い音声は、16 kHz に変換して測ります（備考に注意が出ます。高い音域の特徴は信頼できません）。
- 処理時間の目安（4コアの CPU）：声の特徴量は音声1秒あたり約 0.4 秒、埋め込みは音声1秒あたり ecapa が約 0.08 秒・resemblyzer が約 0.01 秒。同じファイルは1回だけ解析します。例：40人・335ファイル（合計 43 分）の `calibrate` は約 7 分でした。
- ステレオは左右の平均で測ります。

## 6. 開発者向けメモ

- ソース：`src/voicecheck/`、テスト：`src/tests/`（`uv run pytest`）。モデルを読み込めない環境では、埋め込みのテストだけ自動でスキップされます。
- 公開音声（LibriSpeech 由来、CC-BY-4.0）で動作確認する：
  ```
  uv run --with pyarrow --with huggingface_hub python src/scripts/prepare_testdata.py
  uv run voicecheck calibrate --enroll-dir data/testdata/sv_testclean_wavs --out outputs/calib_testclean.xlsx
  ```
  `data/testdata/` に保存されます（Git には入れない）。
- 想定外のエラーで詳細（Traceback）を見たいとき：環境変数 `VOICECHECK_DEBUG=1` を付けて実行する。
- ECAPA モデルは `~/.cache/voicecheck/ecapa`（環境変数 `VOICECHECK_CACHE` で変更可）と Hugging Face の標準キャッシュに保存されます。
- 埋め込みを足すには、`src/voicecheck/embedders.py` の `Embedder` を継承して `REGISTRY` に1行足します。
- ライセンス：このツールは praat-parselmouth（GPL-3.0）を使うため GPL-3.0 互換にしています。speechbrain の ECAPA モデルと Resemblyzer は Apache-2.0、pyworld は MIT です。
