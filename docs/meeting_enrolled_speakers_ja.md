# 会議用：登録した声との照合で「だれが話したか」を決める（speaker_type = enrolled）

pyVideoTrans の話者分離（`built`）は、「声が似ている行をグループに分ける」やり方なので、日本語の会議ではほとんど当たりません
（疑似会議で話者正解率 約50%）。
この改造では、**事前に登録した各人の声に一番近い人の名前**を、字幕の行ごとに付けられます。
設定しなければ、これまでと同じ動作です（`speaker_type` の既定は `built` のまま）。

| | 内蔵 `built` | `enrolled`（登録した声と照合） |
|---|---|---|
| やり方 | 声が似た行をグループにする（教師なし） | 登録した人の中から一番近い人を選ぶ |
| 付く名前 | `spk0`、`spk1`… | **登録フォルダの名前そのもの**（例：`Aさん`） |
| 人数 | 指定が必要。自動は使えない | 登録した人数（指定は無視される） |
| 疑似会議（4人）での話者正解率 | 約50% | **約93〜94%**（重なりなしの録音） |

名前が付くので、`spk0` が誰かを見比べて `speaker_map.json` を書く手間も要りません
（名前は声の複製の手本選びにそのまま使われます。8 章）。

## 1. 使うまでの流れ（3つ準備する）

1. **参加者ごとに声を登録する**（本人の同意を得た声だけ）→ `profiles/` フォルダ（2 章）
2. **話者の特徴を計算するモデル**が `models/onnx/` にあることを確認する（3 章）
3. **設定する**：GUI または CLI（4・5 章）

会議の音声は外に送りません。照合はすべてこのパソコンの中（CPU）で行います。

## 2. 声を登録する

`meeting/src/voiceprofile` の登録ツールで、1人 約3分の朗読から登録フォルダを作ります。
手順は [`meeting/src/voiceprofile/README.md`](../meeting/src/voiceprofile/README.md) の 3-2 章（コマンドはそこからコピーできます）。

```
cd meeting
uv run voiceprofile build --name "Aさん" --in ~/Documents/rec_a.wav --script enroll/script_ja.json --out profiles
uv run voiceprofile build --name "Bさん" --in ~/Documents/rec_b.wav --script enroll/script_ja.json --out profiles
```

できあがり（`profiles` が登録フォルダです）：

```
profiles/
  Aさん/
    profile.json            ← これがあるフォルダが「登録された人」
    refs/ref_ja_01.wav ...  ← 声の再現の手本（照合にも使う）
    eval/eval_ja_01.wav ... ← 取り置きの発話（あれば照合にも使う）
  Bさん/ ...
```

- **フォルダの名前が、字幕に付く名前になります。** 「Aさん」「山田」など、見て分かる名前にしてください。後から変えるときはフォルダ名を変えるだけです
  （声の特徴は中身から計算し直されます）。
- **その会議に出る人のフォルダだけを `profiles` に入れてください。** 欠席の人のフォルダがあると、似た声の人が間違ってその名前になることがあります。
  別のフォルダ（例：`profiles_all`）に全員を置き、会議ごとに出席者だけをコピーするのが安全です。
- 登録の長さは **30秒以上で効果が出ます**（疑似会議で 30秒でも 3分でも同程度）。3分取れば十分です。
- 登録した声の特徴は、人ごとのフォルダに `enrolled_emb_titanet.json` として保存されます（次回から計算を省くためのメモです。
  消しても、手本を差し替えても、自動で作り直されます。個人の声の特徴なので、`profiles` は他人に渡さないでください。Git にも入りません）。

## 3. モデルを確認する

特徴の計算には、`built` が使うのと同じ onnx ファイルを使います。**ダウンロードはしません。**

| `enrolled_speaker_model` | ファイル（`models/onnx/` の中） | 目安 |
|---|---|---|
| `titanet`（既定） | `nemo_en_titanet_small.onnx`（約40MB） | 速い。1時間の会議で数分（CPU 1スレッド） |
| `eres2net` | `3dspeaker_speech_eres2net_large_sv_zh-cn_3dspeaker_16k.onnx`（約116MB） | 精度は同程度、約8倍遅い。登録が10秒だと落ちる |

ファイルが無いときは、画面のログ（CLI では画面）に「話者の特徴を計算するモデルが見つかりません」と出ます。次のどちらかで取得してください。

- いったん `speaker_type` を `built` にして、話者分離を1回動かす（アプリが `models/onnx/` に取得します）。
  ただし、アプリのダウンロード部分は通信の証明書を検証していません（`meeting/docs/research.md` 22章に記載）。
- `meeting` フォルダで `PYTHONPATH=src python -m meetingbench models`（証明書を検証して同じファイルを取得します）。

## 4. 画面（GUI）で使う

1. アプリを閉じて、`videotrans/cfg.json` を開き、登録フォルダを書きます（絶対パス。Windows は `/` で書く）。

   ```json
   {
     "voice_profile_dir": "/Users/あなた/pyvideotrans/meeting/profiles"
   }
   ```

2. アプリを起動し、メニュー「Tools/Options」→「Advanced Options」（高度なオプション）の **「ASR Settings」（音声認識のパラメータ）タブにある、話者分離のモデル（`speaker_type`。英語表示は “Model for speaker separation”）** を `enrolled` にする。
3. 単一動画の画面で **話者分離をオン**にして処理する（人数の欄は「制限なし」のままで構いません。指定しても無視され、登録した人数が使われます）。

## 5. コマンド（CLI）で使う

文字起こし（話者名つきの字幕を作る）。**そのままコピーして、ファイルのパスだけ書き換えてください**：

```
uv run cli.py --task stt --name "D:/会議/meeting.mp4" --detect_language ja --model_name large-v3 --diarize --speaker-type enrolled --voice-profile-dir "D:/pyvideotrans/meeting/profiles"
```

- `--speaker-type enrolled`：登録した声と照合する。
- `--voice-profile-dir`：登録フォルダ（今回の実行だけ有効。`cfg.json` は書き換えません）。`cfg.json` の `voice_profile_dir` に書いてあれば省けます。
- できた字幕（`.srt`）の各行の先頭に `[Aさん]` のように名前が入ります。
- 翻訳・吹き替え（`--task vtv`）でも、同じ3つ（`--diarize --speaker-type enrolled --voice-profile-dir ...`）を足します。
  声の複製の手本には、その人の登録した手本が使われます（8 章）。
- 登録フォルダが空・無い・使える人が1人もいないときは、**処理を始める前に**日本語で理由を出して止まります。

## 6. 結果の読み方（要確認の行を探す）

出力フォルダに、次の3つができます。

| ファイル | 中身 |
|---|---|
| `speaker.json` | 字幕の行順に並べた名前（例：`["Aさん", "Bさん", ...]`）。`built` と同じ形式 |
| **`speaker_diag.csv`** | **まず見るのはこれ。** Excel でそのまま開けます（文字化けしません） |
| `speaker_diag.json` | 同じ内容を機械で読む用（人数・使った手本の数・設定も入っています） |

`speaker_diag.csv` の例：

| 行 | 開始(秒) | 終了(秒) | 話者 | 最高点 | 2位の話者 | 2位の点 | 差 | 要確認 | 理由 | 途中で替わった候補 |
|---|---|---|---|---|---|---|---|---|---|---|
| 1 | 1.70 | 4.67 | Bさん | 0.7432 | Aさん | 0.5067 | 0.2365 | | | |
| 4 | 15.87 | 22.94 | Aさん | 0.6228 | Bさん | 0.5576 | 0.0652 | ● | 1位と2位の差が小さい ／ 話者が途中で替わった可能性 | 15.9-19.4s Aさん / 19.4-22.9s Cさん |

- **最高点**：その行の声と、一番近い登録者の声の近さ（コサイン類似度。1に近いほど似ている。同じ人どうしは 0.6〜0.9 くらい）。
- **差**：1位と2位の点の差。**小さいほど、別の人かもしれません**（0.10 未満で「●」）。
- **要確認（●）の理由**は4種類です。Excel で「要確認」の列を絞り込み、●の行だけ録音を聞いて確かめてください。

  | 理由 | 意味 | どうするか |
  |---|---|---|
  | 1位と2位の差が小さい | 2人のどちらにも似ている | 聞いて、違っていたら字幕の名前を直す |
  | 話者が途中で替わった可能性 | 1行の中で、前半と後半で別の人の声に近い（右端の列に区切りの目安） | 字幕は分けません。行を分けたいときは字幕を手で編集 |
  | 短い／埋め込めないため前の行を引き継いだ | 0.5秒未満の行（「はい」「うん」など）や、音声が取れない行。直前の行と同じ名前にしてあります | 相づちなら多くはそのままで問題なし |
  | 最高点がしきい値未満 | `enrolled_min_sim` を設定したときだけ。名前は `unknown` | 登録していない人かもしれない |

- 疑似会議（4人・336行）では、**間違えた12行はすべて「●」の中に入っていました**（●は72行＝全体の約2割）。
  「●だけ聞けば、間違いのほとんどが見つかる」という使い方ができます。

## 7. 設定項目

`videotrans/cfg.json` に書きます（`speaker_type` は画面からも変えられます）。

| 項目 | 値 | 意味 |
|---|---|---|
| `speaker_type` | `"built"`（既定）／`"ali_CAM"`／`"pyannote"`／**`"enrolled"`** | `enrolled` で登録した声と照合 |
| `voice_profile_dir` | 登録フォルダの絶対パス | 空 `""` だと `enrolled` は使えません（声の複製の手本にも同じフォルダを使います） |
| `enrolled_speaker_model` | `"titanet"`（既定）／`"eres2net"` | 3 章の表 |
| `enrolled_min_sim` | `""`（既定＝使わない）／`"0.55"` など | 最高点がこれ未満の行を `unknown` にする（下の注意を読んでから） |

`enrolled_min_sim`（登録していない人を `unknown` にする設定）は、**既定では使いません**。しきい値は録音の条件で大きく変わるためです。
疑似会議（スタジオ録音）で 3人だけ登録して、登録していない1人の行（78行）を見ると、次のようになりました。

| `enrolled_min_sim` | 登録した人の行が unknown になった数（258行中） | 登録していない人の行が unknown になった数（78行中） |
|---|---|---|
| 0.4 | 1 | 5 |
| 0.5 | 3 | 42 |
| 0.55 | 3 | 50 |
| 0.6 | 14 | 64 |

実際の会議（雑音・反響・マイクの違い）では、全体に点が下がるはずです。**同意を得た模擬会議で「最高点」の分布を測ってから決めてください**
（`speaker_diag.csv` の「最高点」の列がそのまま材料になります）。

## 8. 声の複製（吹き替え）との連携

`voice_profile.py` は、`speaker.json` の名前と同じ名前の登録フォルダを、声の複製の手本に使います
（`speaker_map.json` に載っていないラベルは、ラベルと同じ名前のフォルダを探す決まり）。
`enrolled` が付ける名前は登録フォルダの名前そのものなので、**`speaker_map.json` を書かなくても、A さんの発言は A さんの手本で複製されます。**
`unknown` や、登録のない名前の行は、従来どおりその行の元音声を手本にします。
設定（`clone_ref_mode` など）は [`meeting_voice_profile_ja.md`](meeting_voice_profile_ja.md) を見てください。

## 9. どれくらい当たるか（公開データの疑似会議での現状値）

JVNV（日本語の感情音声）の 4人が交代で話す約32分の疑似会議。登録は会議で使っていない発話（1人 約3分）、字幕の区切りは pyVideoTrans 既定（silero）。
`meeting/src/meetingbench` の採点（`asrcheck`）で測りました。

| 録音 | 条件 | 話者正解率（発言単位） | DER（collar 0） |
|---|---|---|---|
| A（重なりなし） | 内蔵 `built`（日本語） | 50.2% | 58.5% |
| A | **`enrolled`（titanet、登録3分）** | **93.5%** | **18.8%** |
| A | `enrolled`（titanet、登録30秒） | 93.8% | 18.7% |
| A | `enrolled`（eres2net、登録3分） | 93.8% | 19.4% |
| A | 上限（字幕の区切りはそのまま、話者だけ正解にした場合） | 95.3% | 18.1% |
| B（12.5%が重なる） | `enrolled`（titanet、登録3分） | 89.1% | 23.5% |
| B | 上限 | 90.9% | 22.5% |

- 処理時間：約32分の会議で、登録の計算が約15秒、照合が約25秒、途中交代の確認が約55秒（CPU 1スレッド）。登録の計算は2回目から省かれます。
- 残る誤りは、**1つの字幕に2人の声が混ざっている行**だけでした（上限と同じ）。
- 数字は、登録も会議も同じスタジオ録音で、朗読・4人だけという**実際の会議より有利な条件**です。実会議の数字は、同意を得た模擬会議（PLAN の P1-1）で測り直します。

## 10. 限界・注意

- **重なった発話（同時に話している）は、1人にしか名前が付きません。**
- **登録していない人の声は、一番近い登録者の名前になります。** 疑似会議では、登録していない男性の行 78行のうち74行が、声の似た男性の名前になりました。
  `enrolled_min_sim` を設定すれば `unknown` にできますが、7 章のとおりしきい値の決め方に注意が要ります。出席者全員を登録するのが確実です。
- **1つの字幕に2人が混ざる行**は、字幕を分けません（分けると文字起こしのやり直しが必要）。「話者が途中で替わった可能性」の印だけ付きます。
- 声の特徴の計算は英語や中国語のデータで学習したモデルです。日本語でも実測では使えましたが、**実会議（雑音・反響）での精度は未測定**です。
- 風邪・マスク・マイクが違う・オンライン会議の音声（圧縮された声）などで、登録時の声から離れると精度が落ちます。
- 0.5秒未満の行は声から判定せず、前の行の名前を引き継ぎます。
- `speaker.json` はこれまでと同じく、`json.dumps` の標準の書き方なので、日本語の名前は `\u3042` のような記号で保存されます（読むと元の名前に戻ります）。
  人が読むときは `speaker_diag.csv` を使ってください。

## 11. 困ったとき

| 症状 | 見ること |
|---|---|
| 「声の登録フォルダが指定されていません」 | `cfg.json` の `voice_profile_dir`（CLI は `--voice-profile-dir`）。絶対パスで書く |
| 「声の登録が1人も見つかりません」 | `profiles/<名前>/profile.json` があり、そこに書かれた wav が実在するか |
| 「モデルが見つかりません」 | 3 章 |
| 全部同じ名前になる | 登録が1人だけ、または登録の声が似すぎ。`speaker_diag.csv` の「差」の列を見る |
| 名前が違う人になる行が多い | 出席しない人のフォルダを外す。登録を録り直す（静かな部屋・同じマイク）。`eres2net` も試す |
| 登録を差し替えたのに反映されない | `enrolled_emb_titanet.json` は wav の中身が変わると自動で作り直される。それでも変なら、そのファイルを消す |
| 照合が動かず、ログに理由が出る | `logs/` の最新のログで `[enrolled]` を探す |

## 12. 要検証

- モデルのライセンス：NeMo TitaNet small（NGC のモデルカードは「NeMo のライセンスに従う」とのみ）、3D-Speaker ERes2Net（コードは Apache-2.0、重みの記載なし）。
  sherpa-onnx 用に変換された onnx の再配布条件も未確認。**会社で使う前に条文を確認すること**（`meeting/docs/research.md` 24章）。
- 実会議・模擬会議での精度、`enrolled_min_sim` の適切な値。
- 日本語向けの話者埋め込みモデル（より合うものがあるか）。
