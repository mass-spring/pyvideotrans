# voiceprofile（声の登録ツール）

**自分の声を3分ほど録音すると、声の再現に使う「きれいな手本」（10〜15秒×3〜4本）を自動で切り出して、pyVideoTrans が読める形で保存する道具**です。

- 手本の長さ・きれいさ（雑音の少なさ）・音割れ・声の一貫性を測って、いちばん良いものを選びます。
- 手本に使わなかった本人の発話は、あとで「合成した声が本人に似ているか」を測るための**評価用**として取り置きます。
- 結果は Excel（`enroll_report.xlsx`）にまとまります。どの候補がなぜ選ばれたか、どこが怪しいかが分かります。
- パソコンだけ（GPU なし）で動きます。録音は外に送りません。

> **同意なしに他人の声を登録しないでください。** 登録できるのは本人が同意した声だけです（同意文を録音の最初に読みます）。
> 会社の会議音声を、この登録に使わないでください（自分で読み上げた台本の録音を使います）。

## 1. 全体の流れ

| # | やること | 場所 |
|---|---|---|
| 1 | 台本を読んで録音する（同意文＋日本語18文、約2〜3分） | [`enroll/script_ja.md`](../../enroll/script_ja.md) |
| 2 | `voiceprofile build` で手本を作る | この README の 3 章 |

## 2. 準備（最初に1回だけ）

voicecheck と同じ環境を使います（`meeting` フォルダで1回だけ）。uv が無ければ [`src/voicecheck/README.md`](../voicecheck/README.md) の 1-1 を先に。

```
cd meeting
uv sync
uv run voiceprofile --help
```

`build` `map` `script` の説明が出れば成功です。初回の `build` では、声の一貫性を測る ECAPA のモデル（約 85 MB）をネットからダウンロードします（2回目からは不要）。

> 以降のコマンドは、すべて **`meeting` フォルダで**、先頭に `uv run` を付けて実行します（Mac も Windows も同じ）。
> `uv run voiceprofile ...` の代わりに `uv run python -m voiceprofile ...` でも同じです。

## 3. コマンド

### 3-1. 読む台本を画面に出す（任意）

同意文の【　】を自分の情報で埋めた状態で表示します。

**Mac / Windows 共通**
```
uv run voiceprofile script --speaker "山田太郎" --org "株式会社○○" --retention "2027年3月末"
```

### 3-2. 手本を作る（`build`）

録音（例：`rec_yamada.wav`）を用意して実行します。`--name` がプロフィールの名前（フォルダ名）です。

**Mac**（ターミナル）
```
cd meeting
uv run voiceprofile build --name "Aさん" --in ~/Documents/rec_yamada.wav --script enroll/script_ja.json --out profiles
```

**Windows**（PowerShell）
```
cd meeting
uv run voiceprofile build --name "Aさん" --in "C:\Users\あなた\Documents\rec_yamada.wav" --script enroll\script_ja.json --out profiles
```

- `--in`：録音のファイル。**WAV（48 kHz・モノラル）**がおすすめ。m4a などでも読めますが、WAV の方が確実です。スペースが入るパスは `"` で囲みます。
- `--script`：読んだ台本。これを付けると、手本に「読んだ文」が書き起こしとして自動で付きます。付けないと書き起こしは空欄になります（あとで聞いて書き込みます）。
- `--out`：プロフィールを置くフォルダ。`profiles/Aさん/` ができます（`profiles/` は Git に入りません）。
- 数十秒〜数分かかります（時間のほとんどは声の特徴の計測と話者埋め込み。`--no-stats` を付けると短くなります）。

作り直したいとき：すでに同じ名前があると止まります。`--force` で消して作り直し、`--append` で他の言語を足せます（下記）。

#### よく使う追加オプション

| やりたいこと | 付けるもの |
|---|---|
| 録音が2つに分かれた（前半・後半） | `--in rec1.wav --in rec2.wav`（読んだ順に並べる。同意文は1つ目の最初） |
| 日本語のあとに英語・フランス語・中国語も読んだ | `--lang ja,en,fr,zh`（**読んだ順**に。読まなかった言語は省く） |
| 外国語だけ、あとから別の録音で足す | `--lang en --append --no-consent`（`--no-consent`＝その録音には同意文がない） |
| 台本どおりに読めたか自信がない（読み飛ばし・言い直しがある） | `--asr whisper`（下の「ASR」を参照） |
| 台本を使わない／台本以外の話を録った | `--script` を付けない。録音の最初に同意文があれば `--skip-first 3`（最初の3区間を捨てる） |
| 手本の本数・長さを変えたい | `--n-refs 3`、`--min-sec 10 --max-sec 15` など |
| 声の一貫性を測らない（速い） | `--embedder none` |
| 声の特徴（高さ・話速）を測らない（速い） | `--no-stats` |

#### ASR（読み飛ばしがあるときの確認）

台本と録音の対応づけは、普通は「区間の数＝文の数なら順番どおり」で済みます。読み飛ばしや言い直しがあると数が合わなくなり、
その場合は**長さから推定**します（書き起こしの状態が「推定」になります。当たらないこともあります）。
`--asr whisper` を付けると、各区間を faster-whisper で文字にして台本と照合するので、ほぼ正確に対応づけられます。

```
uv sync --group asr
uv run voiceprofile build --name "Aさん" --in rec_yamada.wav --script enroll/script_ja.json --out profiles --asr whisper
```

- 初回だけ ASR のモデル（既定の `small` で約 500 MB）をネットからダウンロードします。録音の音声は外に出ません（手元のパソコンの中で処理）。
- 台本を付けずに `--asr whisper` だけ付けると、書き起こしの**下書き**が付きます（誤認識があるので必ず聞いて直してください）。

### 3-3. 手本を聞いて、書き起こしを確認する

`profiles/Aさん/refs/` の `ref_ja_01.wav` から順に再生して、**`profile.json` の `text`（書き起こし）と合っているか**を確認します。
合っていないときは `profile.json` をメモ帳や VS Code で開き、`text` を直して**UTF-8 で保存**します。
書き起こしの誤りは、声の再現にそのまま響きます（特に手本の文字起こしを使う声複製エンジン）。

### 3-4. 話者ラベルと名前を結びつける（`map`）

pyVideoTrans で話者分離をすると、字幕の行に `spk0`、`spk1`… というラベルが付きます（`speaker.json`）。
どのラベルが誰かを、**1回処理して原文字幕と見比べて**確かめたあとで、対応表を作ります。

**Mac / Windows 共通**
```
uv run voiceprofile map --profiles profiles --set spk0=Aさん --set spk1=Bさん
```

- `profiles/speaker_map.json` ができます：`{"spk0": "Aさん", "spk1": "Bさん"}`。
- 右側の名前は `profiles` の中の**フォルダ名**と同じにします（違うと止まります。それでも書くなら `--allow-missing`）。
- もう一度実行すると、前の対応は残ったまま、指定した分だけ追加・上書きされます。まっさらにするには `--replace`。今の内容は `--show` で見られます。

## 4. できるもの

```
profiles/
  speaker_map.json              ← map で作る対応表
  Aさん/
    profile.json                ← pyVideoTrans が読む。手本の一覧と書き起こし、声の統計など
    refs/ref_ja_01.wav ...      ← 手本（点数の高い順。録音と同じ 48 kHz のまま。音量・ノイズは触っていません）
    eval/eval_ja_01.wav ...     ← 評価用の取り置き（手本に使っていない発話）と eval.json
    emb.npy                     ← 声のセンタロイド（話者埋め込みの平均。あとで似ているかを測る基準）
    enroll_report.xlsx          ← 報告書（4 章）
```

`profile.json` の `refs` は pyVideoTrans の形式そのものです（`wav` は `profile.json` からの相対パス）：

```json
{"wav": "refs/ref_ja_01.wav", "text": "ガスの流量を、…", "lang": "ja", "sec": 12.03, "snr_db": 36.7}
```

そのほか `score`、`text_status`（書き起こしの確かさ）、`consistency`、`src`（元の録音のどこを使ったか）などが付きますが、pyVideoTrans は無視します。
`stats`（声の高さの中央値・抑揚の幅・話速・声の傾き）は、後で合成音声と比べる「本人の基準値」です。

## 5. `enroll_report.xlsx` の読み方

まず「**候補クリップ**」シートを見ます。**緑の行（採用が ◎）が、実際に手本になったもの**です。

| シート | 見るところ |
|---|---|
| **候補クリップ** | 候補すべて。採用（◎）→点数の高い順。`総合点`・`SNR`・`割れ率`・`一貫性`・`書き起こしの状態`・`備考`。赤い数字は注意（SNR 20 dB 未満、音割れ）。黄色は要確認。 |
| 区間 | 録音の中で見つかった発話すべて（時間順）。同意文・読み飛ばし・物音がどう扱われたか、どの文に対応したか。**対応がずれているときはここで分かります。** |
| 評価用クリップ | 手本に使わなかった発話の一覧。 |
| 声の特徴 | 声の高さ・抑揚の幅・話速・声の傾き・CPPS。あとで合成音声と比べる基準値。 |
| **確認事項** | 録音の問題の一覧（サンプリング周波数が低い・雑音が多い・読まれなかった文・雑音が途中で変わった、など）。**空（特にありません）なら問題なし。** |
| 説明 / 実行情報 | 列の意味、作ったときの設定。 |

### 目安

| 列 | 良い | 注意 |
|---|---|---|
| SNR（話し声と雑音の差） | 30 dB 以上 | 20 dB 未満は雑音が目立つ → 静かな部屋で録り直し |
| 割れ率 | 0% | 0.05% を超えると赤。音量を下げて録り直し |
| 長さ | 10〜15 秒（8〜20 秒の範囲） | |
| 一貫性（ecapa） | 0.8 以上 | 0.5 未満は別の声・咳が混ざった疑い → 聞いて確認 |
| 書き起こしの状態 | 「順番どおり（数が一致）」「順番どおり（間の長さでまとめた）」「ASRで確認」 | 「推定」「要確認」「ASRと一致度が低い」は**必ず聞いて確認** |

> 一貫性の水準は埋め込みの種類で違います（resemblyzer は全体に高め）。赤く警告するしきい値は目安で、較正していません。

## 6. pyVideoTrans につなぐ

pyVideoTrans（このフォルダの一つ上）の設定ファイル `videotrans/cfg.json` を、アプリを閉じてから編集します（詳しくは [`docs/meeting_voice_profile_ja.md`](../../../docs/meeting_voice_profile_ja.md)）。

```json
{
  "voice_profile_dir": "/Users/あなた/pyvideotrans/meeting/profiles",
  "clone_ref_mode": "",
  "clone_ref_sample_rate": 44100,
  "max_audio_speed_rate": 1.3
}
```

| 項目 | 意味 |
|---|---|
| `voice_profile_dir` | **このツールの `--out` フォルダ（`profiles`）の絶対パス**。Windows は `"C:/Users/あなた/pyvideotrans/meeting/profiles"`（`/` で書く）。空 `""` なら使わない（従来どおり） |
| `clone_ref_mode` | `""`＝`voice_profile_dir` があれば手本（profile）、なければ従来（line）。`"profile"` / `"line"` で固定もできる |
| `clone_ref_sample_rate` | 手本のない行を、元の音声から切り出すときのサンプリング周波数（既定 44100） |
| `max_audio_speed_rate` | 長さ合わせの早回しの上限（**1.3 を推奨**。本家の既定は 50） |

- 声の複製に対応した配音エンジン（CosyVoice・VoxCPM・GPT-SoVITS・Chatterbox など）で、配音の声に `clone` を選んだときだけ効きます。
- 話者分離は画面（GUI）の単一動画で「話者分離」をオンにし、人数を指定したときだけ動きます。
- 動いたかの確認：`logs/` の最新のログに `clone refs from speaker profiles: 12/12 lines` のような行が出ます。
- 手本を入れ替えたり書き起こしを直したりすると、前回の配音の使い回し（キャッシュ）は自動的に使われなくなります。

## 7. 困ったとき

| 症状 | 対処 |
|---|---|
| `プロフィールがすでにあります` | 作り直すなら `--force`、言語を足すなら `--append` |
| `話している区間が見つかりませんでした` / `音が小さすぎて…` | 録音のレベルが低すぎる、または無音。マイクの音量を上げて録り直す |
| `話し声と雑音の差が小さすぎます` | 部屋が騒がしい／マイクが遠い。静かな部屋で、口から 10〜20 cm で録り直す |
| `手本にできる長さ（8〜20 秒）の発話のまとまりが見つかりませんでした` | 文のあいだの無音が足りない（文が全部つながっている）、または 1 文が長すぎる。文のあいだを1秒あけて録り直す。`--min-pause 0.25` で区間が細かくなることもある |
| 手本が3本取れない | 録音が短い。台本を最後まで読む。確認事項シートも見る |
| 書き起こしの状態が「推定」「要確認」ばかり | 読み飛ばし・言い直しで区間の数が台本の文の数と違う。録り直すか `--asr whisper` |
| 「無音部分が完全に無音」の警告 | 録音ソフトのノイズゲート／ノイズ除去が効いている。切って録り直す |
| 「サンプリング周波数が 44100 Hz 未満」 | 16 kHz などの録音。手本の音質が下がる。48 kHz で録り直す |
| `ASR…を読み込めません` | `uv sync --group asr` を実行。初回はネット接続が必要 |
| `ファイルに書き込めません` | Excel で報告書を開いたまま。閉じてからやり直す |
| 想定外のエラーの詳細を見たい | Mac: `VOICEPROFILE_DEBUG=1 uv run voiceprofile ...` / PowerShell: `$env:VOICEPROFILE_DEBUG=1; uv run voiceprofile ...` |

## 8. 仕組み（ざっくり）

1. **発話区間を見つける**：10 ms ごとの音量から、雑音の床と話し声の大きさを推定し、その中間にしきい値を置く。0.35 秒より短い無音（促音・短い息継ぎ）では区間を分けない。咳・物音・息づかいは、声の周期性（有声のフレームの割合）と webrtcvad で見分けて除く（大きい物音は webrtcvad だけでは声と区別できないので、周期性の判定が主）。
2. **台本と対応づける**：区間の数＝文の数なら順番どおり。読点で息をついて区間が増えたときは、いちばん長い無音を文の切れ目とみなして文にまとめる（切れ目とそれ以外の無音がはっきり離れているときだけ）。それでも合わないときは「読み飛ばし／間をあけずに続けて読んだ／途中で止まった／言い直し」を許す動的計画法で、読む長さ（`--asr` なら文字の一致）から最も自然な対応を探す。同意文は台本の先頭に含めて対応づけ、手本から外す。
3. **手本の候補を作る**：続いた文を丸ごと並べて 8〜20 秒にする（単語の途中では切らない。切り口は無音の中で、前後に 0.12 秒の余白。1 秒近い長い無音は 0.8 秒に詰める）。
4. **測る**：SNR（話し声 対 無音部分の雑音）、音割れ、音量、声の一貫性（ECAPA の話者埋め込みが、同じ録音の他の発話の平均にどれだけ近いか）。
5. **選ぶ**：総合点（SNR 30%・一貫性 25%・長さ 20%・音割れ 10%・書き起こしの確かさ 10%・切れ目 5%）の高い順に、同じ文を共有しないものを3〜4本。取り置きが少なくなりすぎるときは3本に減らす。
6. **書き出す**：手本は録音の波形を切り出して並べただけ（フェード 8 ms 以外、音量・音質・サンプリング周波数は変えない）。

## 9. 限界（正直に）

- **本物の人の声の 48 kHz 録音では、まだ試していません。** 動作確認は、合成音声のテスト録音と、公開音声（LibriSpeech、16 kHz・英語）をつないだ録音です。最初の1人目で、報告書と手本を必ず自分の耳で確かめてください。
- 日本語・フランス語・中国語の ASR（`--asr whisper`）は、英語でしか動作確認していません。
- 長さだけの対応づけ（ASR なし）は、読み飛ばした文を言い当てられないことがあります（文の長さが似ているため。合成の台本で約半分）。そのため「推定」と表示し、点数を下げています。
- 一貫性の点数への写し方（ecapa は 0.5〜0.9）は目安です。録音が少ないので、較正（`voicecheck calibrate`）はしていません。
- 1つの録音に1人だけが話している前提です。他の人の声が混ざると、発話は区別されません（一貫性の値が低く出ます）。
- 雑音が録音の途中で大きく変わると（扇風機の ON/OFF など）、発話区間の判定がずれます。警告は出ます。
- Mac・Windows での実行は未確認です（Linux で確認）。`pyworld` の入れ方などは voicecheck と同じです。

## 10. 開発者向け

```
cd meeting
uv run pytest src/tests/test_voiceprofile_script.py src/tests/test_voiceprofile_segment.py src/tests/test_voiceprofile_align.py \
  src/tests/test_voiceprofile_build.py src/tests/test_voiceprofile_cli.py src/tests/test_voiceprofile_integration.py
```

- `voiceprofile/` の構成：`segment.py`（発話区間）・`align.py`（台本との対応）・`clips.py`（候補と点数）・`quality.py`（SNR・音割れ）・`pipeline.py`（全体）・`profile_io.py`（書き出し・`speaker_map.json`）・`report.py`（Excel）・`asr.py`（任意の ASR）・`script.py`（台本 JSON）・`cli.py`。
- 音声の読み込み・特徴量・話者埋め込み・Excel の部品は `voicecheck` のものを使い回しています。
- テストは `fork` 本体の `videotrans/util/voice_profile.py` を実際に読み込んで、出力が読めることを確かめます（GUI ライブラリが無い環境では、`logger` だけを偽物にして本物のファイルを読み込みます）。
