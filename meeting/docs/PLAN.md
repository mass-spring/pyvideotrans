## 1. 作りたいもの（ゴール）

会議の音声から、次のことを行うアプリ。

| # | 機能 | 内容 |
|---|---|---|
| ① | 話者付き文字起こし | Aさん・Bさん・Cさん…の声を聞き分け、「誰が・いつ・何を言ったか」を記録する |
| ② | 翻訳 | 発言を英語・フランス語・中国語などに訳す |
| ③ | 本人の声で読み上げ | Aさんの日本語の発言を英訳し、Aさんの声で英語として話す |
| 全体 | 感情の読み取り | 怒り・悲しみ・喜びなどを読み取り、②の訳し方と③の声のトーンに反映する |

**作り方（v0.2で決定）**：オープンソースの **pyVideoTrans** をベースにし、
足りない **「感情を読み取る機能（感情モジュール）」を追加**する（D6）。

感情モジュールの用途は2つ（D7）：
- **(a) 声のトーンの再現**：声の複製では声色は似るが、元の発言のトーン（怒り・喜びなど）が再現されない。これを補う。
- **(b) 翻訳内容の調整**：感情・声のトーンに応じて訳の言い回しを変える。

**最重点（v0.3で追加、D8）**：**声の分析と再現**。以前の試行で「声が全然似ていない」問題があったため、
声を「内容・声色・抑揚・感情」に**分解**して分析し、本人らしさを数値で測りながら再現度を上げる（5.4節）。
発想の元は電話の音声符号化（声を「音の高さ（声帯）」と「声色（口・喉の形）」に分けて送る仕組み）。

## 3. 全体構成

```
[会議の録音ファイル]
   │
   ▼  pyVideoTrans（既存の機能）
 ① 文字起こし ＋ 話者分離 ……「誰が・何を」
   │
   ├──▶ ★感情モジュール（新規）……「どんな調子で」
   │      ・発言ごとに元音声を切り出し、感情ラベル＋強さを判定（音声から）
   │      ・文章からの判定（LLM）と組み合わせる
   │      ・結果を発言データに付け、Excelにも出す
   │
 ② 翻訳（LLM） ◀── (b) 感情ラベル・前後の発言・用語集を指示文に入れる
   │
 ③ 声の複製（TTS） ◀── (a) 感情に合わせてトーンを再現
   │      方法の候補：
   │       1. その発言の元音声を声の手本にする
   │       2. 感情を指示できるTTSに感情を指示する（CosyVoice3 等）
   │       3. 合成後に抑揚・強さ・速さを元音声に寄せる（後処理）
   ▼
 出力：翻訳音声／字幕／Excel（話者・発言・感情・訳）
```

- pyVideoTrans は**録音・録画ファイルを処理する方式**（会議中のリアルタイム処理は対象外）。
- 改造は**別モジュールに分け、本体への変更は最小限**にする（本家の更新を取り込みやすくするため）。

## 4. 優先1：ローカル高精度 話者付き日本語文字起こし

> v0.2 注記：以下の手順は、**pyVideoTrans の文字起こし・話者分離部分の評価と強化**として実施する案（Q9）。

### 4.1 処理の流れ

```
録音（WAV、16kHz以上）
 → ① 話者分離：pyannote community-1（参加人数を事前に指定、exclusive 出力を使う）
 → ② 名前付け：事前登録した声と照合して「Aさん」等を付ける
 → ③ 発言区間ごとに文字起こし
       候補：Cohere Transcribe / Qwen3-ASR-1.7B（context に人名・用語）/ Whisper large-v3 / Parakeet-ja
       別案：VibeVoice-ASR-BitNet（CPU専用・約1.6GB、話者分離と文字起こしを一括）も比較に加える
 → ④（任意）複数モデルの結果をローカルLLMで統合・誤字修正（修正前の文も残す）
 → ⑤ 要確認フラグ：モデル間の食い違いが大きい発言、重なり発話、極端に短い発言
 → ⑥ Excel出力：No / 開始 / 終了 / 話者 / 発言 / 修正前 / 要確認
```

### 4.2 精度を上げる工夫（効果が大きい順）
1. **録音環境**：会議用マイクを使う。オンライン会議なら参加者別に録音できる機能を使う（例：Zoom ローカル録画の「参加者ごとに個別の音声ファイルを録音」。話者分離がほぼ不要になる）
2. **参加人数の指定＋声の事前登録**
3. **自分たちの音声でASRを比較して選ぶ**（公開ベンチの順位は当てにならない）
4. **用語集・人名リスト**を文字起こしと補正に渡す
5. **複数モデルの併用＋LLM補正**（ただしLLMが内容を書き換えないよう「最小限の修正」に限定）
6. **人が確認しやすい出力**（要確認の行を色付け）

### 5.1b 声の分析と再現（最重点、D8）

**考え方：声を4つに分解して、それぞれ正しい出どころから組み立て直す**

| 要素 | 中身 | 出どころ |
|---|---|---|
| 内容 | 何を話すか（訳文） | 翻訳結果 |
| **声色（本人らしさ）** | 声の高さの平均、口・喉の響き（フォルマント）、声質 | **本人の登録音声（事前に集める）** |
| 抑揚 | 音の高さの動き、強さ、速さ、間 | 元の発言（言語の違いを考慮して移す） |
| 感情 | 怒り・喜び・悲しみ等とその強さ | 感情モジュール |

**「似ない」原因の仮説（要因分析。V2 で1つずつ検証する）**

> コード調査で確認した事実（research.md 10・12章）：pyVideoTrans の複製の手本は**字幕1行ごとの元音声を 16kHz で切り出したもの**で、本人ごとの手本・品質の選別はない。長さ合わせの加速は**既定で最大50倍**まで許可。→ 仮説1・2・5・6 は実際に起こりうる構造になっている。

1. 手本音声が悪い（会議の雑音・反響・重なり発話・電話音質・短すぎる・16kHz）
2. 話者分離の誤りで、他人の声が手本に混ざる
3. 手本音声の書き起こしが不正確（F5-TTS などは正確な書き起こしが必要）
4. 言語をまたぐと声色がずれる（日本語の手本→英語の合成）
5. 3秒程度の「その場で複製（ゼロショット）」の限界 → **本人ごとの追加学習**が効く可能性
6. 長さ合わせの早回しで声が変わる（pyVideoTrans は訳音声を元の長さに合わせて速度変更する）

## 8. リスク

| リスク | 対策 |
|---|---|
| 声の複製の悪用・同意なし利用 | 本人同意を必須にし、合成音声は「AI翻訳音声」と明示する |
| 社内データの外部流出 | ローカル処理を基本にし、クラウドは模擬データのみ（D4） |
| ライセンス違反 | 商用利用可のモデルに限定（SeamlessExpressive などの非商用モデルは使わない）。独自ライセンスの emotion2vec+（FunASR）、IndexTTS（bilibili）、TranslateGemma（Gemma 規約）は採用前に条文を確認 |
| **非商用の重みが pyVideoTrans の選択肢に含まれる**（F5-TTS・OmniVoice・Higgs は非商用、IndexTTS は大企業は別契約） | 使わない。候補は VoxCPM2・CosyVoice3・Chatterbox・GPT-SoVITS（Apache/MIT）。emotion2vec+ は法務確認 |
| **pyVideoTrans は GPL-3.0** | 社内で使うだけなら公開義務は生じないのが一般的。**社外に配布する場合は改造部分も含めソース公開が必要**。配布の予定が出たら社内の法務に確認 |
| 本家 pyVideoTrans の更新で改造が壊れる | 改造は別モジュールに分け、本体の変更を最小限にする。取り込む版を固定する |
| 重なり発話・雑音で精度低下 | マイク環境の改善、要確認フラグ |
| 公開ベンチと実際の会議で精度が違う | 自前の評価データで選定（P1-1, P1-3） |
| 感情認識が会議音声で当たらない（多くは平常） | 音声と文章の判定を組み合わせる。強さが低い時はトーン調整を弱める |
| MacBook Airの熱による減速 | 長時間処理の実測、必要なら分割処理 |
