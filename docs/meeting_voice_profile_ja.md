# 会議用：話者ごとの声の手本（voice profile）の使い方

pyVideoTrans の「声の複製」は、そのままだと **字幕1行ごとの元音声（数秒・雑音入り・16kHz）** を手本にします。
そのため行ごとに声がばらつき、本人に似にくくなります。
この改造では、**事前に用意した「きれいな本人の手本」を話者ごとに使う**ことができます。
設定しなければ、これまでと同じ動作です。

## 1. 何が変わるか

| | 従来（本家） | 改造後（profile 使用時） |
|---|---|---|
| 声の手本 | その行の元音声 | 話者ごとに登録した手本（10〜20秒） |
| 手本の書き起こし | その行の原文字幕 | 手本に付けた書き起こし（人が確認したもの） |
| 手本の音質 | 16kHz | 登録した音質のまま（44.1/48kHz） |
| 手本のない話者・行 | — | 従来どおりその行の元音声を使う（ただし 44.1kHz で切り出し） |

## 2. profiles フォルダを作る

```
profiles/
  speaker_map.json          ← 話者ラベルと名前の対応表（任意）
  Aさん/
    profile.json
    refs/
      a_01.wav
      a_02.wav
  Bさん/
    profile.json
    refs/
      b_01.wav
```

### 手本の録り方（効果が大きい順）
1. 静かな部屋で、口元に近いマイクで録る。**ノイズ除去・人声分離はかけない**。
2. 1人 **10〜20秒の手本を3〜5本**（1本は12秒前後が目安）。1人の声だけで、咳・笑い・重なりがないもの。
3. 48kHz（または44.1kHz）・モノラル・WAV で保存する。録音から切り出すコマンド例（ffmpeg）：
   ```
   ffmpeg -i 録音.m4a -ss 00:00:05 -t 14 -ac 1 -ar 48000 -c:a pcm_s16le a_01.wav
   ```
4. **何を話しているかを人が聞いて書き起こす**（間違いがあると声の再現が崩れます）。
5. 本人の同意を得た声だけを使う。会議の録音・手本をクラウドに上げない。

### profile.json の書き方
`wav` は、この profile.json があるフォルダからの相対パスです。

```json
{
  "name": "Aさん",
  "refs": [
    {"wav": "refs/a_01.wav", "text": "えー、今期の目標値についてご説明します。", "lang": "ja", "sec": 14.2, "snr_db": 32.1},
    {"wav": "refs/a_02.wav", "text": "それでは次の議題に移りましょう。", "lang": "ja", "sec": 11.8, "snr_db": 30.4}
  ]
}
```

- `lang`：手本の言語（ja / en / fr / zh）。
- `sec`（秒）、`snr_db`（きれいさ）：省略してもよい。省略した手本は選ばれる順位が下がります。
- 手本の選び方：①元の発言と**同じ言語**の手本 → ②`snr_db` が高い手本 → ③長さが12秒に近い手本（20秒を超えた分は数えない）。

## 3. 話者ラベルと名前を結びつける（speaker_map.json）

話者分離をすると、字幕の各行に `spk0`、`spk1`… というラベルが付き、出力フォルダの `speaker.json` に
**字幕の行順**で保存されます（例：`["spk0", "spk1", "spk0"]`）。
1回処理してから、`speaker.json` と原文字幕を見比べて、spk0 が誰かを確認してください。

`profiles/speaker_map.json`：
```json
{"spk0": "Aさん", "spk1": "Bさん"}
```

- 右側の名前は **profiles 内のフォルダ名**と同じにします。
- 対応表に書かなかったラベルは、**ラベルと同じ名前のフォルダ**（例：`profiles/spk2/`）があれば使います。
- どちらもない話者、話者ラベルが取れない行は、従来どおりその行の元音声を使います。
- 話者分離は画面（GUI）の単一動画で「話者分離」をオンにし、人数を指定したときだけ動きます（`cli.py` では動きません）。

## 4. 設定を変える

アプリを閉じてから `videotrans/cfg.json` を開き、次の項目を追加・変更します（無ければ起動時に初期値で作られます）。

| 項目 | 値 | 意味 |
|---|---|---|
| `voice_profile_dir` | `"/home/user/profiles"`（絶対パス。Windows は `"C:/Users/名前/profiles"`） | 空 `""` なら無効（従来どおり） |
| `clone_ref_mode` | `""`（既定）／`"profile"`／`"line"` | `""` は「`voice_profile_dir` があれば profile、なければ line」。`"line"` で従来の動作に戻せる |
| `clone_ref_sample_rate` | `44100`（既定） | 行ごとの手本を切り出すときのサンプリング周波数。従来は 16000 |
| `max_audio_speed_rate` | `1.3`（**推奨**。本家の既定は 50） | 長さ合わせで訳音声を早回しする上限。50倍まで許すと声が変わる |

```json
{
  "voice_profile_dir": "/home/user/profiles",
  "clone_ref_mode": "",
  "clone_ref_sample_rate": 44100,
  "max_audio_speed_rate": 1.3
}
```

- 本家のままだと `1.3` は整数の `1` に切り捨てられて**早回しが全く効かなくなる**ため、改造で小数も読めるようにしてあります（`configure/_app_settings.py`）。
- `max_audio_speed_rate` を小さくすると、訳が長い行は元の時間枠からはみ出します（訳を短くする工夫は今後の課題）。
- 声の複製に対応した配音エンジン（CosyVoice・VoxCPM・GPT-SoVITS・Chatterbox など）で、配音の声に `clone` を選んだときだけ効きます。
- 手本ファイルは処理用フォルダに**コピーして**使うので、GPT-SoVITS のように手本を10秒に切る配音エンジンでも、元の profiles は壊れません。

## 5. 動いたかの確認

- `logs/` の最新のログに `clone refs from speaker profiles: 12/12 lines` のような行が出ます（左が profile を使った行数、右が声の複製の行数）。
- 手本を入れ替えたり書き起こしを直したりすると、前回の配音の使い回し（キャッシュ）は自動的に使われなくなります。

## 6. 期待される効果と限界

- 期待：行ごとの声のばらつきが減り、本人らしさが上がる（調査上、手本の取り方が最大の要因。`docs/research.md` 12章）。効果は **V2・V3 で話者類似度を測って確認する**（数値は未測定）。
- 言語をまたぐ（日本語の手本 → 英語の合成）と、類似度は下がります。
- 一方、手本は**その発言の抑揚・感情を含みません**。トーンの再現は別の仕組み（感情モジュール）で行う予定です。
- 手本の中身（雑音・書き起こしの誤り）は結果にそのまま影響します。うまくいかないときは、まず手本を録り直してください。
